An open source Claude skill for construction teams

From project manual to submittal register

Give Claude a specification PDF. It finds every submittal requirement, applies the project's Division 01 rules, and builds a register where each row cites its spec section, paragraph and page. When transmittals and stamped returns come in, a second skill updates the register for you.

How it works

A script for structure, Claude for judgment

The parts that must be exact are done by code. The parts that need reading comprehension are done by Claude, and anything uncertain is flagged for a person.

1

Read the structure

A script indexes the manual's sections, finds each submittals article, and splits it into items with the spec section, paragraph and page.

2

Apply judgment

Claude reads the Division 01 rules, adds closeout and administrative items, merges related ones, and flags what it is unsure about.

3

Build the register

The register is stored as plain data and written out as Excel, CSV, JSON or Google Sheets values. The Excel version has project rules, a review queue and a section summary, with date formulas that update when you enter install dates.

A column layout file sets which columns appear, their headers and their order, and lets a team add its own, such as Ball in Court or Trade.

Keep it current

Upload a transmittal or a stamped return, the register updates

You choose the project by choosing its register, then upload the documents. Claude reads them, and code decides where each change goes and whether it makes sense.

1

Read and match

Claude turns each document into events: sent for review, or returned approved, approved as noted, revise and resubmit, or rejected. The matcher finds the register line from the spec section and the wording.

2

Ask when unsure

Lines that read alike, items that are not in the register, and documents whose project name does not fit the register go to you. Nothing is guessed.

3

Apply and log

Status, dates, revision and ball in court are updated, a backup is kept, and every change goes in an audit log. Uploading the same document twice changes nothing.

How well does the matching work? On two public registers (51 and 243 lines) with the wording shortened, reworded and put in plural, it was never confidently wrong, and it asked a person for a small share of lines that read nearly alike. It has not been tried on real project paperwork yet, so the first real documents are the real test.

Compare

What changed between two registers

Give Claude two registers for the same project and say which is old. It reports the differences that matter and leaves out the ones that do not.

1

Match

Submittals are paired within each spec section, then across sections for anything that moved. Case, plurals, punctuation, row order and numbering are ignored.

2

Classify

Added, deleted, moved to another section, or changed in type or approval requirement. Status and date changes go on their own sheet.

3

Summarize

Claude settles the borderline pairs and leads with the big picture: a new section, a block of items that changed type, a section that changed a lot.

One real test so far. An owner's 1,519-line register against one generated from the specification gave a readable report with a handful of pairs to confirm. Items renamed and moved in the same step show as one deleted and one added.

Verify

Built to be checked, not trusted blindly

A register that nobody can audit is worse than no register. The output is designed so a person can confirm it quickly.

How to check a register

  • Page-check ten random rows against the PDF.
  • Read the Review Queue. Each flag says why.
  • Compare rows per division with the table of contents.
  • Recompute three dates by hand.

Read the full verification guide

What it does not do

  • It does not read scanned PDFs. It needs a text layer.
  • It runs one file at a time. For split volumes, it lists every section it could not find.
  • Submittals written inside construction paragraphs come through as review rows, not finished rows.
  • Intake has no OCR, so scanned stamps are read by eye and are worth a second look. It does not read Gmail yet, because each project needs its own label or sender list first.
  • The Google Sheets output follows the connector's format but has not been run against a live sheet.

Try it

Four steps

  1. Download the zip and unzip it into your Claude skills, or copy the submittal-register folder from GitHub.
  2. Attach a project manual PDF and ask for a submittal register.
  3. Optionally give install dates by spec section so required submit dates calculate.
  4. Later, add the intake skill, choose the register and upload transmittals or stamped returns. The repository has four fictional sample documents to try it on.
python3 scripts/extract.py manual.pdf draft.csv
python3 scripts/build_register.py reviewed.csv \
  Register.xlsx --rules rules.json --save-json

python3 scripts/intake.py match register.json events.json -o matches.json
python3 scripts/intake.py apply register.json matches.json --dry-run
Check the work. The skill flags what it is unsure about, but a person should confirm those rows and spot-check pages against the manual before the register is issued.
